# Техническое задание на Telegram-бота для выбора блюд

## 1. Назначение продукта

Telegram-бот помогает пользователю решить повседневную проблему: **«Что приготовить сегодня?»**

Основная идея продукта — не создавать ещё один каталог рецептов, а дать пользователю возможность сформировать **собственную базу привычных блюд**, которые он реально готовит и ест, а затем быстро получать подходящие варианты на основе продуктов, которые есть дома или которые пользователь хочет использовать.

Бот должен работать как персональный помощник по выбору еды.

Ключевая ценность продукта:

* уменьшить время на принятие решения;
* напоминать пользователю о блюдах, которые он уже знает;
* помогать выбирать блюда исходя из конкретных продуктов;
* не требовать каждый раз вспоминать весь свой рацион;
* сделать выбор ужина или завтрака максимально быстрым.

---

# 2. Основные сущности продукта

## Блюдо

Блюдо — основная единица пользовательского каталога.

Каждое блюдо должно иметь:

* название;
* тип блюда;
* список ингредиентов;
* возможность добавления в избранное;
* возможность редактирования;
* возможность удаления.

Тип блюда:

* ☕️ Завтрак;
* 🍗 Обед/ужин.

В дальнейшем допускается добавление других типов, однако для первой версии достаточно этих двух.

---

## Ингредиент

Ингредиент — продукт, входящий в состав одного или нескольких блюд.

Например:

* курица;
* лук;
* морковь;
* картофель;
* рис;
* яйца;
* сыр.

Один ингредиент может использоваться во множестве блюд.

Ингредиенты должны быть организованы таким образом, чтобы пользователь мог быстро находить их как через кнопки, так и через текстовый ввод.

---

# 3. Главный экран

После запуска пользователь видит главное меню.

Основные кнопки:

**🍽 Подобрать по продуктам**

**🎲 Что приготовить?**

**📚 Мои блюда**

**➕ Добавить блюдо**

**⭐ Избранное**

**⚙️ Настройки**

Главный экран должен быть максимально простым. Пользователь не должен видеть большое количество второстепенных действий.

Главные сценарии использования должны начинаться непосредственно с этих кнопок.

---

# 4. Функциональные требования

## F1. Добавление блюда

Пользователь должен иметь возможность добавить новое блюдо в свою персональную базу.

Сценарий:

1. Пользователь нажимает **➕ Добавить блюдо**.
2. Бот предлагает ввести название блюда.
3. Пользователь вводит название.
4. Бот предлагает выбрать тип блюда:

   * ☕️ Завтрак;
   * 🍗 Обед/ужин.
5. После выбора типа пользователь добавляет ингредиенты.
6. Бот показывает итоговую карточку блюда.
7. Пользователь подтверждает сохранение.

Перед сохранением должны быть доступны действия:

* ✅ Сохранить;
* ✏️ Изменить название;
* 🥕 Изменить ингредиенты;
* 🔄 Изменить тип блюда;
* ❌ Отмена.

После сохранения блюдо появляется в разделе **Мои блюда** и начинает участвовать в подборе.

---

# 5. F2. Добавление ингредиентов к блюду

Добавление ингредиентов должно быть максимально быстрым.

Пользователь должен иметь два способа добавления.

### Способ 1. Через кнопки

Пользователь выбирает категорию продукта.

Пример категорий:

* 🥩 Мясо и птица;
* 🐟 Рыба и морепродукты;
* 🥕 Овощи;
* 🍎 Фрукты;
* 🍚 Крупы;
* 🍝 Макароны;
* 🥛 Молочные продукты;
* 🧀 Сыры;
* 🥚 Яйца;
* 🍞 Хлеб и выпечка;
* 🫘 Бобовые;
* 🌿 Зелень;
* 🧂 Соусы и приправы;
* 📦 Другое.

После входа в категорию пользователь видит список продуктов в виде кнопок.

Например:

**🥕 Овощи**

* Картофель
* Лук
* Морковь
* Помидоры
* Огурцы
* Перец
* Кабачок
* Баклажан
* Чеснок

При нажатии ингредиент добавляется к выбранным.

Повторное нажатие снимает выбор.

---

### Способ 2. Через текст

Пользователь может написать:

«курица, лук, морковь, картошка»

Бот должен определить отдельные ингредиенты и предложить добавить их.

После распознавания бот показывает:

**Выбрано:**

✅ Курица
✅ Лук
✅ Морковь
✅ Картофель

Пользователь может подтвердить или изменить список.

---

# 6. F3. Просмотр выбранных ингредиентов

При добавлении продуктов пользователь всегда должен понимать, что уже выбрано.

Бот показывает блок:

**Выбрано: 4**

Курица ×
Лук ×
Морковь ×
Картофель ×

Должны быть доступны кнопки:

* ➕ Добавить ещё;
* 🗑 Очистить;
* ✅ Готово;
* ⬅️ Назад.

---

# 7. F4. Просмотр каталога блюд

Раздел **📚 Мои блюда** показывает персональную базу пользователя.

На первом уровне:

* ☕️ Завтраки;
* 🍗 Обеды/ужины;
* ⭐ Избранное;
* 🔎 Поиск.

Рядом с категориями желательно отображать количество блюд.

Например:

☕️ Завтраки — 8
🍗 Обеды/ужины — 24

После выбора категории пользователь получает список блюд.

---

# 8. F5. Карточка блюда

При выборе конкретного блюда пользователь видит карточку.

Пример:

**🍗 Курица терияки**

Тип: Обед/ужин

Ингредиенты:

* курица;
* рис;
* соевый соус;
* чеснок;
* мёд.

Доступные действия:

* ⭐ В избранное;
* ✏️ Редактировать;
* 🗑 Удалить;
* ⬅️ Назад.

Если блюдо уже находится в избранном, вместо кнопки «В избранное» отображается возможность убрать его из избранного.

---

# 9. F6. Редактирование блюда

Пользователь должен иметь возможность изменить любое созданное им блюдо.

Можно изменить:

* название;
* категорию блюда;
* список ингредиентов.

После редактирования обновлённые данные сразу используются в подборе.

---

# 10. F7. Удаление блюда

Пользователь может удалить блюдо.

Перед удалением требуется подтверждение:

**Удалить «Куриный суп»?**

* 🗑 Да, удалить;
* ❌ Отмена.

Случайное удаление в одно нажатие недопустимо.

---

# 11. F8. Избранные блюда

Пользователь может отмечать любимые блюда.

Раздел **⭐ Избранное** должен показывать только отмеченные блюда.

Избранные блюда также могут получать небольшой приоритет при рекомендациях в режиме случайного выбора.

---

# 12. F9. Подбор блюда по продуктам

Это основной сценарий продукта.

Пользователь нажимает:

**🍽 Подобрать по продуктам**

Далее выбирает:

* ☕️ Завтрак;
* 🍗 Обед/ужин;
* 🍽️ Все блюда.

После этого бот спрашивает:

**Какие продукты ты хочешь использовать?**

Пользователь выбирает один или несколько ингредиентов.

Например:

* курица;
* лук;
* морковь.

После подтверждения бот показывает список подходящих блюд.

---

# 13. F10. Рейтинг подходящих блюд

Блюда должны быть отсортированы по степени соответствия выбранным ингредиентам.

Главный принцип:

**чем больше выбранных пользователем продуктов входит в блюдо, тем выше оно отображается.**

Пример:

Пользователь выбрал:

* курица;
* лук;
* морковь.

Блюдо 1 содержит:

* курицу;
* лук;
* морковь.

Оно должно отображаться выше.

Блюдо 2 содержит:

* курицу;
* лук.

Оно отображается ниже.

Блюдо 3 содержит только курицу.

Оно отображается ещё ниже.

Таким образом, выбор нескольких ингредиентов не означает, что блюдо обязано содержать их все.

---

# 14. F11. Отображение совпадений

В результатах подбора пользователь должен сразу видеть, почему конкретное блюдо было предложено.

Пример:

**🍗 Куриный суп**

Совпало: **3 из 3 выбранных продуктов**

✅ Курица
✅ Лук
✅ Морковь

Дополнительно нужны:

* картофель;
* вермишель.

Так пользователь понимает не только степень совпадения, но и чего ему не хватает.

---

# 15. F12. Режим «Хочу блюдо с этим продуктом»

Для некоторых сценариев пользователь хочет обязательно использовать конкретный ингредиент.

Например:

**«Сегодня я хочу курицу»**

В таком случае блюда без курицы не должны отображаться.

Пользователь может выбрать один основной продукт и дополнительные продукты.

Пример:

Основной продукт:

🎯 Курица

Дополнительные:

Лук
Морковь

Тогда:

* все результаты обязательно содержат курицу;
* блюда с луком и морковью получают более высокий рейтинг.

---

# 16. F13. Быстрый выбор ингредиентов

Чтобы пользователю не приходилось каждый раз открывать категории, бот должен предоставлять быстрые списки.

Разделы:

* 🔥 Частые;
* 🕘 Недавние;
* ⭐ Избранные продукты;
* 📂 Все категории;
* 🔎 Поиск.

Частые продукты должны определяться на основе использования пользователя.

Например:

Курица
Яйца
Картофель
Лук
Рис
Макароны

---

# 17. F14. Поиск ингредиента

Пользователь может начать вводить название продукта текстом.

Например:

«кур»

Бот должен предложить подходящие варианты:

* Курица;
* Куриное филе;
* Куриные бёдра.

Это должно облегчать работу с длинным каталогом.

---

# 18. F15. Нормализация названий продуктов

Разные варианты названия одного продукта не должны создавать хаос в каталоге.

Например:

«куриная грудка»
«грудка»
«филе курицы»

могут относиться к одному базовому ингредиенту.

Пользователю должно отображаться понятное название, например:

**🍗 Курица**

Цель — исключить появление множества дублей одного продукта.

---

# 19. F16. Базовые продукты

Некоторые продукты обычно всегда есть дома и не должны мешать подбору.

Например:

* соль;
* перец;
* вода;
* растительное масло;
* сахар.

Пользователь может указать список продуктов:

**«Считать всегда имеющимися»**

Такие продукты не должны ухудшать рейтинг блюда и не должны постоянно отображаться как недостающие.

---

# 20. F17. Режим «Что приготовить?»

Пользователь может не знать ни блюдо, ни конкретные продукты.

Для этого существует кнопка:

**🎲 Что приготовить?**

После нажатия пользователь выбирает:

* ☕️ Завтрак;
* 🍗 Обед/ужин;
* 🍽 Всё.

Бот предлагает несколько блюд из персонального каталога.

Например:

**Сегодня можно приготовить:**

🍗 Курица терияки
🍝 Болоньезе
🍗 Куриный суп

Кнопки:

* 🔄 Другие варианты;
* ⭐ Избранное;
* 👨‍🍳 Выбрать блюдо;
* ⬅️ Назад.

---

# 21. F18. Повторная генерация вариантов

В режиме случайного выбора пользователь должен иметь возможность нажать:

**🔄 Ещё варианты**

и получить другой набор блюд.

Желательно не показывать одни и те же блюда несколько раз подряд, если в базе достаточно других вариантов.

---

# 22. F19. Фильтр по типу еды

В любом сценарии просмотра или подбора пользователь должен иметь возможность ограничить результаты:

* только завтраки;
* только Обеды/ужины;
* все блюда.

Например, омлет не должен постоянно конкурировать с пловом при выборе вечернего блюда, если пользователь выбрал категорию «Обед/ужин».

---

# 23. F20. Поиск блюда

В разделе **Мои блюда** пользователь может найти блюдо по названию.

Пример:

Пользователь вводит:

«кур»

Бот показывает:

* Куриный суп;
* Курица терияки;
* Куриная паста;
* Курица с овощами.

---

# 24. F21. Быстрое добавление нового ингредиента

Если нужного продукта нет в каталоге, пользователь должен иметь возможность добавить его прямо во время создания блюда.

Например:

Пользователь вводит:

«соус шрирача»

Если такого ингредиента нет, бот предлагает:

**Не найдено. Добавить новый ингредиент «Соус шрирача»?**

* ✅ Добавить;
* ✏️ Изменить название;
* ❌ Отмена.

---

# 25. F22. Настройки

Раздел **⚙️ Настройки** должен позволять пользователю управлять персонализацией.

Минимальный набор:

* управление ингредиентами;
* базовые продукты;
* управление категориями;
* просмотр или очистка частых продуктов;
* управление персональными настройками подбора.

Настройки не должны перегружать главный интерфейс.

---

# 26. F23. История выбора блюд

Бот должен иметь возможность учитывать, какие блюда пользователь недавно выбирал.

В будущем это позволит не предлагать одно и то же блюдо слишком часто.

В интерфейсе может существовать раздел:

**🕘 Недавно готовил**

Это не обязательная часть первого запуска продукта, но сценарий должен быть предусмотрен.

---

# 27. F24. Отметка «Приготовил»

При открытии блюда пользователь может нажать:

**✅ Приготовил**

Это действие фиксирует блюдо как недавно приготовленное.

В дальнейшем история используется для более разнообразных рекомендаций.

---

# 28. F25. Умное случайное предложение

Режим «Что приготовить?» в перспективе не должен быть полностью случайным.

При выборе можно учитывать:

* тип блюда;
* избранное;
* недавно приготовленные блюда;
* часто выбираемые блюда;
* блюда, которые давно не готовились.

Основная цель — помогать пользователю вспоминать забытые варианты и не предлагать постоянно одно и то же.

---

# 29. F26. Возможные теги блюд

Блюдо может иметь дополнительные характеристики:

* ⚡ Быстро;
* 🕐 До 30 минут;
* 🥗 Лёгкое;
* 🍖 Сытное;
* ❄️ Можно приготовить заранее;
* 👨‍🍳 Требует готовки;
* 🥪 Без готовки.

На первом этапе теги можно не делать обязательными, но структура продукта должна позволять добавить их позже.

---

# 30. F27. Подбор по тегам

В будущем перед подбором пользователь может дополнительно указать пожелание.

Например:

**Какое блюдо хочется?**

* ⚡ Быстро;
* 🍖 Сытно;
* 🥗 Легко;
* 🤷 Неважно.

После этого результаты должны учитывать выбранную характеристику.

---

# 31. F28. Сохранение пользовательского каталога

Все добавленные блюда, ингредиенты, избранное и настройки должны быть персональными.

Каждый пользователь имеет собственную базу блюд.

Один пользователь не должен видеть или изменять блюда другого пользователя.

При этом стандартный список ингредиентов может быть общим.

---

# F29. Семья и совместный каталог блюд

Пользователь должен иметь возможность объединиться с другим пользователем в **семью** и совместно использовать каталог блюд.

В главном меню или настройках должна быть кнопка:

**👨‍👩‍👧 Моя семья**

Внутри раздела:

* 👥 Участники семьи;
* 🔗 Пригласить в семью;
* 🚪 Выйти из семьи.

При нажатии **«Пригласить в семью»** бот создаёт персональное приглашение. Основной вариант — специальная Telegram-ссылка, которую пользователь может скопировать и отправить другому человеку.

Дополнительно может использоваться короткий код приглашения. Новый пользователь нажимает **«Вступить в семью»**, вводит код и подтверждает присоединение.

Перед вступлением бот должен явно сообщить:

**«Вы присоединяетесь к семье пользователя [Имя]. После подтверждения ваши каталоги блюд будут общими.»**

Кнопки:

**✅ Вступить**
**❌ Отмена**

После объединения пользователи становятся участниками одной семьи. Каждый из них должен видеть **все блюда всех участников** в разделах «Мои блюда», поиске, избранном и подборе по ингредиентам.

Если один участник добавляет, редактирует или удаляет блюдо, изменения должны быть доступны остальным участникам семьи. Новые блюда автоматически попадают в общий каталог.

При необходимости возле блюда можно отображать автора:

**Добавил: Алексей**

При выходе из семьи пользователь снова работает со своим личным каталогом. Блюда других участников перестают быть ему доступны.

Главная задача функции — позволить людям, которые живут или питаются вместе, вести **единую базу привычных блюд** и получать рекомендации с учётом рациона всей семьи.

# 32. Основной пользовательский сценарий

Типичный сценарий должен выглядеть следующим образом:

1. Пользователь открывает бота.
2. Нажимает **🍽 Подобрать по продуктам**.
3. Выбирает **🍗 Обед/ужин**.
4. Выбирает:

   * курицу;
   * лук;
   * морковь.
5. Нажимает **✅ Показать блюда**.
6. Получает:

**1. Куриный суп — совпало 3/3**

**2. Курица с овощами — совпало 3/3**

**3. Курица терияки — совпало 2/3**

**4. Куриная паста — совпало 1/3**

7. Пользователь открывает подходящее блюдо.
8. Видит ингредиенты, которые уже выбрал, и продукты, которые понадобятся дополнительно.
9. Принимает решение, что приготовить.

Весь сценарий должен занимать минимальное количество действий.

# 33. Сценарий первого использования

При первом запуске у пользователя нет блюд.

Бот должен объяснить основную механику:

**Я помогу решить, что приготовить.**

Для начала добавь несколько блюд, которые ты обычно готовишь.

Кнопки:

* ➕ Добавить первое блюдо;
* ℹ️ Как это работает.

После добавления нескольких блюд бот может предложить:

**Отлично. Теперь можно попробовать подобрать блюдо по продуктам.**

Кнопка:

**🍽 Попробовать подбор**

# 34. Требования к интерфейсу

Интерфейс должен соответствовать нескольким принципам.

### Минимум ручного ввода

Где возможно, пользователь должен выбирать варианты кнопками.

При этом текстовый ввод должен существовать как быстрый альтернативный способ.

### Минимум переходов

Основные действия должны выполняться за несколько шагов.

### Всегда понятное состояние

Во время выбора пользователь должен понимать:

* где он находится;
* что уже выбрано;
* что произойдёт после следующего действия.

### Возможность вернуться назад

Практически на всех вложенных экранах должна быть кнопка:

**⬅️ Назад**

### Возможность отменить действие

При создании или редактировании должна быть:

**❌ Отмена**

### Подтверждение опасных действий

Удаление данных должно требовать подтверждения.

# 37. Что не является целью первой версии

Чтобы продукт не превратился в сложную систему учёта продуктов, на первом этапе не требуется:

* вести точное количество еды в холодильнике;
* учитывать граммы ингредиентов;
* автоматически списывать продукты после приготовления;
* учитывать сроки годности;
* вести полноценный список покупок;
* рассчитывать калории;
* создавать диетические планы;
* хранить пошаговые рецепты;
* автоматически генерировать рецепты;
* считать стоимость блюда.

Основная задача продукта:

**помочь пользователю быстро выбрать одно из тех блюд, которые он уже любит и умеет готовить.**

# 38. Критерий успешности продукта

Бот можно считать успешным, если пользователь может открыть Telegram в момент, когда он не знает, что приготовить, и за несколько действий получить несколько релевантных вариантов из собственного привычного рациона.

Главный пользовательский результат:

**«Я не знал, что приготовить → открыл бота → выбрал несколько продуктов → получил подходящие блюда → выбрал ужин».**

Все дополнительные функции должны усиливать именно этот сценарий, а не усложнять его.
